(21 fichiers, 203 tests), `tsc --noEmit`, ESLint avec `.eslintrc.json`, `npm run build`, migrations et RLS sur un Postgres

## Décisions

- **E1 · Discord : tout en éphémère.** Chaque réponse de commande porte le drapeau 64 (visible de l'auteur seul) : un
  membre Pro qui tape `/produits` dans un salon ouvert ne montre pas le classement du jour aux autres.
- **E2 · Mêmes règles que l'appli.** Compte Discord → profil → plan (`getProfileByDiscordId`). `/produits` et
  l'autocomplétion appliquent `rankForUser` + `visibleProductIds` (Gratuit : ses 3 produits du jour et ceux qu'il suit,
  score masqué ; jamais un nom verrouillé, même en autocomplétion). `/score` et `/script` comptent dans
  `discordCommandsPerDay` (3 / 30 / 100) : une fiche `commande_discord` par commande, comptée depuis minuit (Paris) ; une
  commande ratée est rendue. Non lié : message qui explique `/lier`.
- **E3 · Limite des 3 secondes** (doc `interactions/receiving-and-responding`). Sans IA : réponse immédiate (type 4).
  `/script` : réponse différée (type 5, éphémère), puis `PATCH /webhooks/{application.id}/{interaction.token}/messages/@original`
  (jeton valable 15 min, sans jeton de bot). Sur Netlify le travail part dans la fonction d'arrière-plan
  `discord-interaction-background` (202 immédiat, 15 min, protégée par `CRON_SECRET`), car une fonction ordinaire s'arrête
  à la réponse ; ailleurs, dans le même processus. Lancement refusé ⇒ réponse d'erreur immédiate, commande rendue. Le jeton
  d'interaction est retiré des messages d'erreur.
- **E4 · Accroche `/script`** : `askStructured` (schéma Zod accroche + idée), garde-fou `lib/ai/guard.ts`, un second essai,
  puis une accroche sûre écrite par le code. Sans clé : accroche d'exemple, signalée comme telle.
- **E5 · Format de la fiche `alerte`** (même format appli / Discord, `lib/discord/alerte.ts`) :
  `{ niche: NicheId | null, minCommissionPercent: number, minSales7d: number | null, minGrowth: number | null, active: boolean }`
  — `niche` null = toutes ; `minCommissionPercent` en % du prix (15 = 15 %) ; `minSales7d` = ventes cumulées sur 7 jours ;
  `minGrowth` en **ratio** comme `Product.growth_7d` (0,2 = +20 % ; `/alerte croissance:20` enregistre 0,2), une
  croissance non mesurable ne le remplit pas ; `active` false = en pause, hors limite. Limite d'alertes **actives** =
  `PLANS[plan].alerts`. `parseAlerte` valide, `matchesAlerte(product, alerte)` sert au moteur de la nuit.
- **E6 · Salon public = la veille.** Public : le relevé de la veille (5 produits, en clair, sans score, liens vers
  `/tendances` et `/prix`) ; Pro : le relevé du jour complet avec scores (salon à réserver au rôle Pro dans les permissions
  Discord). Si le relevé du jour n'est pas encore fait, le public n'a rien (il aurait la même chose que les Pro).
- **E7 · Classement des séries** : opt-in (`/classement rejoindre|quitter|voir`, fiche `reglages_discord
  { classement }`, aussi `setLeaderboardOptIn` pour un réglage dans l'appli). Le lundi à `DISCORD_LEADERBOARD_HOUR`
  (10 h), une fois (tâche réservée), dans `DISCORD_LEADERBOARD_CHANNEL_ID` : 10 premiers, mention Discord + nombre de jours,
  `allowed_mentions: { parse: [] }` (personne n'est notifié). Pas de message s'il n'y a personne. Série par défaut = jours
  consécutifs avec un script écrit, une commande `/score`·`/script` ou une vidéo marquée postée ; remplaçable par la vraie
  source des séries (`setStreakSource`).
- **E8 · RGPD formateur.** Sans consentement : uniquement des agrégats (inscrits, actifs 7 j, abonnés, en essai,
  résiliés, vidéos postées = somme de `saved_products.videos_posted`, scripts, produits suivis). Le détail d'un élève
  (prénom, plan, statut, vidéos, scripts, code, dernière visite) n'apparaît que s'il l'a accepté (fiche
  `consentement_formateur { coach_id, detail, updated_at }`, une par élève, révocable) ; l'e-mail suit toujours
  `profiles.share_email_with_coach`. Un accord donné à un autre formateur ne compte pas.
- **E9 · Plusieurs codes par formateur** : fiches `code_formateur { code, label, active }` du formateur (10 au plus, en plus
  du code principal), uniques face aux codes principaux, de parrainage et supplémentaires. L'inscription avec n'importe
  lequel rattache au formateur (même essai de 3 mois) et note le code (`rattachement_formateur { coach_id, code }`). Un code
  en pause ne marche plus ; les élèves inscrits restent rattachés.
- **E10 · Page co-brandée `/f/[code]`** : nom de la formation, offre de 3 mois, bouton vers `/r/[code]` (cookie 30 jours puis
  inscription). Non indexée (une page par code, contenu presque identique). Les liens affichés suivent
  `NEXT_PUBLIC_SITE_URL` (aujourd'hui splendorous-kleicha-5d07d3.netlify.app) : ils deviennent `tracktout.com/f/CODE` dès que
  le domaine `BRAND_DOMAIN` est branché et réglé dans cette variable, sans changement de code (un lien vers un domaine pas
  encore en ligne serait cassé).
- **E11 · Annonces** : `notify(type 'annonce', push)` à chaque élève, lien vers `/app/consentement-formateur` où l'élève relit
  les annonces ; 3 par jour au plus (fiches `annonce_formateur`).
- **E12 · Versements manuels.** Solde = commissions (après remboursements) − versements (fiches `versement
  { amount_cents, paid_on, reference }`, écrites par l'admin, jamais au-delà du solde). Un remboursement après versement
  rend le solde négatif (retenu sur le suivant). Prochain versement : début du mois suivant si le solde atteint 50 €
  (hypothèse de RAPPORT.md).
- **E13 · Fiches écrites par le serveur seul** : migration `20261115400100_fiches_serveur.sql` — `versement`,
  `code_formateur`, `rattachement_formateur`, `commande_discord`, `annonce_formateur` restent lisibles par leur
  propriétaire mais ne peuvent plus être créées, modifiées ni supprimées depuis le navigateur (sinon : effacer un versement,
  remettre un quota à zéro, s'attribuer un code). Testé dans `supabase/tests/rls_test.sql`.
- **E14 · Kit de partage** : 3 textes (4 pour un formateur) sans chiffre ni promesse ; visuels PNG générés par
  `ImageResponse` (`next/og`) en carré 1080², story 1080×1920 et bannière 1200×630, fond noir, dégradé cyan → rose, code et
  lien de la personne connectée (`/app/parrainage/visuel/[format]`, téléchargeables). Police : celle de `next/og` (Sora
  n'existe qu'en woff2, que Satori ne lit pas).
- **E15 · Indicateurs admin** : MRR = abonnements `active`/`past_due` × prix du plan (annuel ÷ 12), TTC et HT (TVA 20 %) ;
  essais à part ; Stripe seul s'il existe, sinon le simulé (signalé). Conversion = payants ÷ inscrits (et cohorte 30 j).
  Résiliations = abonnements finis sur 30 j + programmées. Actifs par jour : relevé de la veille chaque nuit
  (`recordDailyMetrics`, cache serveur 400 jours, jamais inventé pour un jour sans relevé ; bouton « Relever la veille »).
- **E16 · Coûts** : Nexscope depuis `cron_runs.details` de la tâche nocturne (appels, vidéos, lots de détails) × crédits
  (recherche 22, vidéos 11, lot de détails 96 : doc + appels mesurés) ; en euros seulement si
  `NEXSCOPE_EUR_PER_1000_CREDITS` est donné. IA : jetons non enregistrés ⇒ générations × jetons mesurés (script
  1 300 + 3 800, gpt-6-luna) ou supposés (autre appel 1 500 + 2 000) × prix connus (décision 115) ; modèle inconnu ⇒ « prix
  inconnu ». Marge = MRR HT − commissions − frais Stripe (1,5 % + 0,25 €, à vérifier) − Nexscope − IA − fixes, par abonné
  payant, avec la liste de ce qui manque. Toutes les hypothèses sont affichées sous le calcul.
- **E17 · `/tendances`** : relevé de la **veille** (les abonnés ont celui du jour), sans score ni script. Relevé du jour pas
  encore fait ⇒ le catalogue affiché ; sinon, dernier instantané antérieur de chaque produit, classé par son score de ce
  jour-là, calculé une fois par jour et gardé dans `provider_cache`. Seuil : **5 vrais produits** par catégorie
  (`MIN_PRODUCTS_PER_NICHE`), 12 affichés. En dessous, ou en base fictive : 404 et absente du plan du site ; l'index
  `/tendances` n'est indexé et listé que s'il a une catégorie. JSON-LD `ItemList` (position + nom, rien d'inventé), échappé.
  Pages recalculées au plus toutes les heures (`revalidate = 3600`).
- **E18 · Fichiers hors du périmètre listé, créés faute de mieux** : `netlify/functions/discord-interaction-background.mts`
  (E3), `lib/tendances.ts` (sélection partagée par le salon public et `/tendances`), `lib/og.tsx` (visuels partagés),
  `app/opengraph-image.tsx` (image de partage par défaut). Aucun fichier interdit n'a été modifié.
